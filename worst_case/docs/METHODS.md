# Methods: exact and certified worst-case optimisation of Shellsort gap sequences

All code is in `src/` (C, OpenMP) and `scripts/` (Python, stdlib only). Build with `build.ps1`.

## 0. Cost model

Gapped insertion sort, largest gap first; every evaluation of `a[j-h] > t` is one comparison
(`src/core.h`). Gaps `>= N` are no-ops, so a "sequence" is a set `G ⊂ {1..N-1}` containing 1.
This convention reproduces the reference table exactly (N=6..10 by brute force: 14, 18, 23, 29, 35).

For an element at chain index `t` that has `a` smaller elements before it in its chain, the
insertion costs `t − a + [a > 0]` comparisons (`t−a` shifts, plus one failing comparison unless it
becomes the chain minimum).

## 1. Exact worst case of one sequence (N ≤ 64)

### 1.1 Threshold-set decomposition
A permutation is a maximal chain of *threshold sets* `∅ = S_0 ⊂ S_1 ⊂ … ⊂ S_N`
(`S_v` = positions holding values `< v`). Sorting commutes with thresholding, so the set of
positions holding values `< v` *before pass j* is a deterministic image `T_j(S_v)`, and the comparisons
charged to value `v` in pass `j` depend only on `(T_j(S_{v-1}), T_j(S_v))`. Hence the total cost is a
sum of edge weights along the chain and **the worst case is a longest path in a lattice of sets**.
Each image is computed in O(#chains) with popcounts on 64-bit masks; the position of the new
element after pass `j` is `chain + (#smaller in chain)·h`.

### 1.2 Decoupling the first pass
Every g₁-sorted array π₁ is the image of the input that reverses each g₁-chain of π₁, and that
input makes the first pass cost its absolute maximum `A = Σ m(m−1)/2`. Therefore
`W(G) = A + max_{π₁ g₁-sorted} cost_{passes 2..k}(π₁)`, and the DP runs over g₁-downsets
(count vector per g₁-chain, mixed-radix index): `Π (m_r+1)` states (`src/exact.h`).

### 1.3 Absorbing pair passes and the back-fill lemma (`src/exact2.h`)
A pass with `2h ≥ N` has chains of length ≤ 2: it is `N−h` disjoint compare-exchanges, costs
exactly `N−h`, and its possible outputs are exactly the linear extensions of the poset `P_H`
generated by `x[i] < x[i+h]`. So `W = Σ_{h∈H}(N−h) + max_{π ∈ LE(P_H)} cost_rest(π)`.
The next pass (gap ℓ) is decoupled: its output σ is tracked by threshold sets while its own cost
is charged where each value lands inside its ℓ-chain of π.

**Back-fill lemma.** Positions not involved in any `P_H` relation ("free") can be filled
back-to-front within each ℓ-chain without loss. Proof sketch: swapping the fill times of two
free positions `x<y` (fill `y` first) never lowers intermediate costs (their `a` can only drop) and,
writing the cost as `t − d(a)` with `d(a)=max(a−1,0)` convex and non-decreasing, the two swapped
steps satisfy `d(α+β)+d(α+γ) ≤ d(α)+d(α+β+γ+δ+1)`. σ (hence all later passes) is unaffected.
The state becomes *(downset F of P_H on constrained positions, #free filled per ℓ-chain)*, which is
exponentially smaller when the top gap is near N (e.g. {1,4,7,9,29} at N=30: 8·10⁸ → 9.8·10⁵ states,
153 s → 0.1 s). The best number of absorbed passes is chosen automatically.

**Front pair rules** (`x2_front_rules`, modes `dp2r` / `layr`). Absorbing costs states: every pair adds
constrained positions. When every pair `(x, x+h)` of the leading pair passes joins the *first* position
of one ℓ-chain to the *last* position of a different ℓ-chain (h ≥ N − ℓ, h not a multiple of ℓ), the
constraint `π[x] < π[x+h]` acts only through the order in which chains receive their values, so the
pairs need not be absorbed. A lower-end chain A loses nothing if its smallest value sits at x and the
rest follow in decreasing order. An upper-end chain B loses max(0, j − 2) comparisons when its j-th
smallest value sits at its last position, and that value must exceed every partner's smallest value. In
the threshold-set DP this becomes: placing B's 2nd … (m−1)-th value before all of B's partner chains have
received their first value costs one comparison, and placing B's last value then is not allowed. The
state space is that of the sequence *without* those passes, e.g. {1,4,9,11,21,44} at N = 46 runs on the
3.3·10¹⁰ states of {1,4,9,11,21} (6.6 GB) instead of absorbing 44 (18.9 GB). From any state, giving the
partner chains their first values first avoids every penalty, so the one-byte floor of §1.4 still holds.
The reconstructed input is rearranged chain by chain as described and re-simulated.

### 1.4 Parallel and memory-lean variants
* `dp2p`: blocks with the same |F| are independent → processed level by level in parallel.
* `lay` (`src/layered.h`): every transition places exactly one value, so only two consecutive
  levels are stored. States inside a level are ranked in O(1) with a two-group mixed-radix split
  (`rank = offL[F] + offB[s][idx_B] + posA[idx_A]`).
  - **One byte per state.** At level L (L values placed) every remaining value costs ≥ 1 comparison in
    each pass unless it lands on one of that pass's h chain heads, so `f ≥ floor(L) = Σ_j max(0, N−L−h_j)`.
    The DP stores `f − floor(L)` in a byte; an out-of-range residual aborts the run (never occurred).
  - **Memory-aware decomposition.** The number of absorbed pair passes is chosen to minimise *total*
    bytes (both levels plus the per-F offset tables, sized by convolution), with a hard 12 GB cap.
    E.g. {1,4,9,11,21} at N = 45 (2.48·10¹⁰ states) runs in 5.1 GB / 11 min on 24 threads.
  - **Input reconstruction.** Optionally every level is written to disk; a forward walk then picks, at
    each level, a move with `cost + f(successor) = f(current)`, yielding an attaining input
    (`scripts/reconstruct.py`). Levels are written in 128M-cell chunks, because a single msvcrt `fwrite`
    of more than 4 GiB slows to about 1 MB/s.
  - **16-bit cells.** Sequences with few passes and a heavy final pass can exceed the one-byte residual
    (detected; the run aborts). E.g. {1,4,9,33} at N = 45, the README's average-optimal sequence.
    `bin/shellwc16.exe` (built with `-DLAY_CELL=uint16_t`) stores two bytes per state; that instance
    then needs 10.0 GB, 2.5·10¹⁰ states, 9 min.

### 1.5 Exact average case
A uniform input makes π₁ uniform over g₁-sorted arrays (each has `Π m_r!` preimages), i.e. uniform
over maximal chains of the same lattice; one backward sweep with path counts gives the exact mean.
When that lattice is too large (top gap near N), the average is estimated from 2·10⁷ random inputs
(standard error ≈ 0.005), which is enough to order all ties found here.

### 1.6 Validation
* DP = brute force (all N! inputs) on 40 random sequences with N ≤ 11 and 75 random sequences at
  N = 12 (479M inputs each), plus N = 13 spot checks (6.2·10⁹ inputs each).
* DP2 = plain DP on 150 random sequences (N ≤ 18); layered = DP2 on 60 random sequences (N ≤ 26);
  the one-byte layered DP reproduces all known exact values it was tested on.
* Front pair rules = DP2 on 300 random sequences of that form (N ≤ 24; the constraints change the
  value in 214 of them), each with a re-simulated attaining input (`scripts/test_rules.py`). At full
  size they reproduce two values certified by the general layered DP: {1,4,9,11,21,45} = 394 at N = 46
  (11 min instead of 23) and {1,4,9,11,21,44} = 380 at N = 45 (8.5 min instead of 27).
* Every certified optimum has a stored attaining input, re-simulated independently in pure Python
  (`scripts/verify.py`; zero contradictions over all stored witnesses).
* Exact averages = full enumeration for N ≤ 10.

## 2. Certified lower bounds (any N ≤ 1024)

* Simulated annealing over g₁-sorted arrays (first pass decoupled) with value-adjacent,
  value-near, position-near and random swaps (`src/anneal.h`). A hot start (T₀≈3) matters for large N.
* **Value-window large-neighbourhood move** (`src/vlns.h`): reordering the values `v0..v0+w−1`
  among their own positions only changes the comparisons charged to those values, so the optimal
  reordering is found exactly by a DP over the `2^w` subsets of window positions, carrying all pass
  images incrementally (`T_j(S+q) = T_j(S)+{q_j}`). This is a joint move over many inversions, used to
  polish annealing results.
* Every reported value is attained by a concrete input permutation that is re-simulated.
* **Incremental evaluation** (`src/fastsa.h`): per value v and pass j the threshold set T[v][j], the
  position of v before pass j and its cost are stored; swapping values x < y only changes S_u for
  x < u ≤ y, so a move costs O((y−x+1)·passes·words) instead of a full simulation (~100× faster for
  value-adjacent swaps at N = 362). Checked against full simulation on 2.9M random moves (N = 12…362).

### 2.1 Comparing sequences at large N: the winner's curse and adversarial checks
Ranking sequences by a lower bound favours sequences whose worst inputs are merely hard to find. At
N = 64 the beam's first apparent winner {1,4,9,11,32,62} (≥ 627) was shown by the reference author's
hill-climber to reach 631 (reproduced here by a targeted search in 16 s). Large-N verdicts are therefore
adversarial: `scripts/challenge.py` / `attack_all.py` run a *targeted* search (restart until an input
reaching the target is found, or a restart budget is exhausted) against every candidate whose bound is
below the reference sequence's best-known value. A candidate is only called better if it survives; even
then the claim is "best known under this budget", never a proof (an 80-restart survivor at N = 64 was
later shown to reach 631 by the reference author's search).

### 2.2 Restart length, calibration and Luby restarts
Which restart length finds a sequence's worst inputs depends on the sequence, so a race run with one fixed
length is biased. At N = 64, 144 long runs (200M moves each) never went above 630 for {1,4,9,11,21,60} and
{1,4,9,11,21,62}, yet 4M-move restarts reached 631 for them after 288 and 24 restarts (21 s and 2 s).
Conversely {1,4,9,11,21,57} needed 3,509 short restarts for a 631 that long runs found easily. Slow cooling
seems to settle in broad basins, while fast quenches sample narrow high peaks. Consequences:
* `fwc` reports the best input over *all* restarts (it used to report the last one) and the number of
  restarts used; `FSA_LUBY=1` switches to the Luby restart schedule (run lengths 1,1,2,1,1,2,4,… × base,
  `scripts/race.py --tag luby`), which is within a logarithmic factor of the best fixed restart length for
  any unknown run-time distribution.
* **Calibration.** A race is informative only if its budget re-finds a value that a contender is already
  known to reach; such a contender is attacked fresh (`race.py --fresh`). At N = 64 this check fails at
  632: the reference sequence {1,4,9,11,21,61}, known ≥ 632 from one lucky long run, survived 144 long
  runs, 3,048 Luby restarts and 2,880 *seeded* restarts at 631. (Seeded restarts start each anneal from a
  stored worst input of another N = 64 sequence, `FSA_SEEDS` / `race.py --seeds auto`, at T₀ = 0.3–1.2.)
  Its 632 input is atypical. The 21-pass is one comparison below its maximum (65 of 66), and the 11-pass
  costs 113 against 116–119 for the 631-inputs of its {1,4,9,11,21,·} neighbours. The loss is recovered in
  the later passes, a global trade-off that local moves rarely make. The seven sequences that also
  "survived" the race to 632 are therefore *not* shown to be better. They are tied with it at the level
  that can be measured reliably (631).
* **Calibrated verdicts** (`scripts/round3.py`, Luby restarts; every race includes a contender already known
  to reach the target). The values keep rising with effort, and the reference sequence reaches every level
  eventually, so each verdict holds "at this budget". It is still informative, because the budget is the
  same for all contenders and is shown to be enough for the others.
  - N = 91: the reference sequence reaches 1045, so its earlier lone survival of a long-run race at 1045
    was an artefact. It is the only one of eight not pushed to 1046, in 3,048 and again 6,120 restarts,
    while the other seven needed 24–2,255.
  - N = 128: at 1661 the reference sequence survived 3,048 restarts (the runner-up needed 248) and reached
    it only on the last of 6,120 at double budget. At 1662 it is the only one of three not pushed there
    (3,048 restarts; the others needed 547–719).
  - N = 181: every contender reaches 2632, 2635 and 2637. At 2640 the reference sequence is the only one
    of seven not pushed there (1,512 restarts; the others needed 72–1,512).
  - N = 256: every contender reaches 4152 and 4160. At 4165 the reference sequence is the only one of five
    not pushed there (1,512 restarts, best 4163; the others needed 168–744).
  - N = 362: every contender, the reference sequence included, reaches 6429, 6440 and 6450, so it
    remains a tie at the highest level measured. The later fixed-budget attacks (one long anneal per
    thread, no target; `docs/CAMPAIGN_362.md`) pushed all four contenders well above that level, to
    6517–6560 at 1G moves per thread (the reference sequence to 6556, and to 6576 at 2G).
  - In all ten races at N ≥ 91 where several contenders reached the same level, the reference sequence
    needed the most restarts or tied for the most. Its worst inputs are the rarest, which is consistent
    with, but no proof of, a lower true worst case. This does not hold at N = 64, where it reached 631
    after 120 short restarts while others needed 288 or 3,509.

### 2.3 Parallel tempering (`fsa_pt` in `src/fastsa.h`, mode `pt`, `BATCH_PT`)
Each thread runs its own replica-exchange ladder: R replicas at temperatures geometric in
[T_min, T_max], `mpe` Metropolis moves per replica (the swap mix of the annealer, incremental
evaluation) between exchange attempts of neighbouring temperatures (even and odd pairs alternately;
acceptance min(1, exp((E_hot − E_cold)(1/T_cold − 1/T_hot))) for the maximised cost E). An improved best is
window-DP polished every 64 rounds. It replaces restarts: hot replicas keep re-randomising while cold ones
keep the deep basins, so rare high peaks are reached without restarting from scratch. On five N = 64
sequences at equal moves (32M per thread, 4 threads, two seeds) the setting below beat Luby-restarted
annealing in all 10 runs, by 1–5 comparisons (README sequence 631/631 against 628/630; {1,4,9,11,32,62}
reached 632, a value no earlier race had found for it). In 2M-move screening runs it adds about 2
comparisons on average (R = 8, mpe = 1000). The advantage depends on the size: at N = 91, with 100M moves
per thread, the same ladder (R = 12, T ∈ [0.3, 2.0]) reached 1042/1043 for {1,4,9,11,30,44} against
1044/1045 for Luby restarts. A hotter ladder (R = 16, T ∈ [0.3, 3.0], mpe = 1000) tied them there (1045/1044)
but still trailed on {1,4,9,11,32,44} (1042/1043 against 1045/1047); a colder, longer ladder (R = 24,
T ∈ [0.2, 3.0]) was worse (1040/1042). So N = 64 attacks use R = 12, T ∈ [0.3, 2.0], mpe = 2000, and N = 91
attacks alternate Luby restarts and the hot ladder between rounds (`scripts/maxout.py --method`).
At N = 128 and 181 the ladder falls behind (100M moves per thread, 24 threads): at N = 128 it reached
1651–1652 / 1659–1664 for {1,4,9,11,30,36,59} / {1,4,9,11,30,47,48} against 1652–1658 / 1666–1675 for Luby
restarts; at N = 181, 2620 / 2631 for {1,4,9,11,30,47,59,86} / {1,4,9,11,30,58,81} against 2628–2633 /
2657–2663. Longer restart bases and a hotter start help there: 4M-move restarts from T₀ = 4.5 beat 2M from
T₀ = 3 by 5–6 at N = 181, and T₀ = 4.5 gives the highest 2M-move screening scores at both sizes. The
N = 128 / 181 campaigns (`docs/CAMPAIGN_128_181.md`) therefore use Luby restarts only (`--base 2–8M`,
`--T0 3–4.5`), and screen with annealing from T₀ = 4.5 (`famscan.py --T0`).
The trend continues at larger N. At N = 256 the screens anneal from T₀ = 9, and the rounds alternate 4M-move
restarts from T₀ = 4.5 with 16M-move restarts from T₀ = 9, since neither won on both test sequences
(`docs/CAMPAIGN_256.md`). At N = 362 longer anneals won at every step tested, up to one anneal of the whole
budget per thread. At 100M moves per thread, 4M-move restarts from T₀ = 6 reached 6437 / 6453 on the two test
sequences and 32M-move restarts from T₀ = 13 reached 6483 / 6502; at 128M, one anneal reached 6521 / 6560
against 6516 / 6541 for two of half the length. The N = 362 rounds therefore give each thread one anneal
(`maxout.py --base` = `--moves`, T₀ = 13), and the screens anneal from T₀ = 13 (T₀ = 9–18 are level;
`docs/CAMPAIGN_362.md`). The N = 512 rounds use the same settings; the N = 512 screen anneals from T₀ = 9
(`docs/CAMPAIGN_512.md`).

### 2.4 Beam search over the threshold-set DP (`src/beam.h`, mode `beam`)
The exact DP of §1 places values in increasing order; a state is the down-set S of g₁-chain positions
holding the values placed so far, and the cost charged to the next value depends only on S. The beam keeps,
per level, the B states with the largest accumulated cost (duplicates merged, equal costs broken at random),
so its result is a real input. It reaches the exact optimum 394 of {1,4,9,11,21} at N = 46 with B = 10⁶
(393 with B = 10⁵), but at N = 64 it stalls at 627 for the README sequence (632 known), even after a
low-temperature anneal from its result (629): ordering by accumulated cost is too myopic there. It is kept
as an independent cross-check, not used for the bounds below.

## 3. Sequence search: parallel branch-and-bound with continuous pruning (`src/seqsearch.c`)

* **Search tree over prefixes.** A node is `P = {1=p₁<…<p_m}` (the *last* passes). Its family
  `F(P)` = P and all its extensions by larger gaps.
* **Family bound.** If `x` is *p_m-local* (`x[i] < x[j]` whenever `j−i > p_m`), every pass with gap
  `> p_m` leaves `x` untouched, so **every** member of `F(P)` costs at least `cost_P(x)` on `x`.
  One local permutation with `cost_P(x) > T` prunes the whole family. Down the tree the parent's
  witness gives `cost_{P∪{g}}(x) = cost_P(x) + N − g`, so the bound only tightens.
* **Continuous pruning.** Every witness found (killer input) is kept in a per-thread pool and tried
  first on every subsequent node; the shared threshold `T` only decreases. Sequences are evaluated in
  stages: cold greedy climb → hot anneal → (if the DP would be expensive) long anneal → exact DP.
  Only exact values lower `T`, so every pruning decision is backed by an input that costs more than a
  proven value: the final optimum and the **complete** tie set are rigorous.
* **Holistic moves.** Candidates are always whole sequences, generated by the tree, never by
  perturbing one gap of an incumbent; at large N the tree can be restricted to families extending a
  set of prefixes, so all larger gaps are re-optimised jointly.
* **Parallelisation.** Depth-1 nodes and depth-3 subtrees `{1,a,b}` are independent OpenMP tasks;
  certification DPs are parallel internally.
* **Certification loop** (`scripts/run_search.py`). Candidates whose exact DP exceeds the in-search
  limit are first attacked with a strong anneal and otherwise certified with `dp2p`/`lay`; if a better
  certified value appears, the search is re-run from it so the tie list at the final value is complete.
* **Tie-break.** Among sequences with the optimal worst case, the one with the lowest average
  comparison count is reported (same rule as the reference). The average is exact where the §1.5 lattice
  fits, and otherwise sampled from 2·10⁷ inputs (N = 27, 30, 33–41, 43–46; standard error ≤ 0.0021, while
  the closest gap between two tied sequences is 0.047).
* **Manual certification** (`scripts/manual_cert.py`). Tie candidates whose DP exceeds the driver's
  caps are either excluded by a targeted search that finds an input above W* (witness stored) or
  certified with the one-byte layered DP, then merged. At N = 43–45 this settled seven candidates
  (four certified exactly, three excluded by inputs above W*).

## 4. Large N (N ≥ 64): prefix-transfer beam (`scripts/transfer.py`)

The exhaustive tree was attempted at N = 64 and abandoned: the locality bound is weak for prefixes built
from small gaps, so families like {1,3,…} and {1,4,5,…} stay open for hours. Instead:
1. **Candidates** are complete sequences: each of this work's best sequences at the previous size,
   truncated by 0–2 of its largest gaps, plus 0–2 (or 0–3) new largest gaps chosen *jointly* on a grid
   (gaps ≤ N/2 for N ≥ 91, as in the reference). A diversified chain starts at N = 91 from the whole
   {1,4,9,·,·,·}, {1,4,7,9,·,·}, {1,4,10,·,·,·} families (≈ 29 000 sequences).
2. **Screening**: one-thread incremental annealing per candidate (10⁶ moves), the best ~60 re-run with
   10⁷ moves, finalists chosen round-robin across 4-gap families, then multi-thread strong runs.
3. **Adversarial verdicts** (§2.1) against the reference sequence's best-known value.
